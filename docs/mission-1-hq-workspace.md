# HQ content workspace rollout

Branch: feature/hq-content-workspace, based on the Fast Upload feature branch. No main app or Play release changes. No new dependencies. Existing bulk import endpoint and previous Fast Upload RPC remain available.

Backend: docs/mission-1-hq-workspace.sql adds three admin-only invoker RPCs: hq_language_content_metrics (server aggregate per theme, linked-asset counts, not media quality checks), check_vocabulary_edit_draft (exclude current ID, lock scope), hq_edit_vocabulary (snapshot compare under import lock and row lock, check duplicates, verify selected storage paths, keep ID/theme/position, preserve links unless specifically changed). No destructive migration. Existing manual CRUD permissions remain unchanged. Metrics errors display unavailable, not zero. Existing legacy external links are retained until changed. A valid legacy slug is stable; missing/invalid slugs are generated upon save. Corrections may require resolving a slug collision. Editing media creates a new immutable version; old objects are retained even if unlinked. Explicit removal unlinks only on save. Failed DB edits may leave unlinked new media, never auto-delete. No background mass migration.

Language Add/Edit uses the same Vocabulary Studio. Existing Adventure editor remains available with old manual URL workflow to avoid expanding scope. Browser engine setup is inherited from Fast Upload. Validate locally: flutter pub get; flutter analyze; flutter test test/vocabulary_import_test.dart test/vocabulary_fast_upload_test.dart test/content_workspace_test.dart; flutter run -d chrome (or windows). Verify metrics, search, filters, all navigation actions, thumbnails, play/stop, create & next, edit legacy text-only entry with real image and audio, preserve its ID and position, replace existing media without changing another card, discard, stale edit, network failure and bulk/Adventure regression. Use one verified test record before mass editing. Do not merge before local tests. Rollback: switch back to feature/vocabulary-asset-pipeline; additive RPCs are compatible and can remain installed.
