Local draft, 500ms read-only validation, canonical filenames, preview, explicit publish. Term reuse with another meaning is allowed after review; exact duplicate or slug/file conflict blocks create. Existing bulk imports retain missing-link recovery. Shared concept images are available through both bulk import and Fast Upload. Choose Reuse Existing Image to browse/search the global images directory and preview an existing image from any language. The existing path is linked, never copied or overwritten. Missing selected objects block publication even when missing media is allowed. Clear the initial definition-based filename search to browse all images. Audio remains language-specific. Original filenames are reported when present in the relevant folder; only canonical target collisions block upload. File bytes are retained for the current draft only. A failed database commit may leave uploaded but unlinked assets; retry after revalidation reuses byte-identical assets, never auto-deletes. For an uncertain response check the vocabulary list first.

## Adaptive audio input

Fast Upload on Windows/macOS/Linux accepts MP3, WAV, M4A, AAC, OGG, OPUS, FLAC, AMR and 3GP when a compatible FFmpeg installation is on PATH. MP3 remains unchanged; other formats are converted locally to 96 kbps mono MP3, 44.1 kHz, and preview uses the converted bytes. Original file is untouched. Input limit 50 MB for non-MP3, 10 MB for MP3; output limit 10 MB. Conversion times out after 60 seconds; invalid or unsupported recordings fail closed. No cloud conversion, new Dart package, schema, bucket, or public app changes. Native mobile and the existing batch-manifest importer remain MP3-only. Chrome uses the separate same-origin FFmpeg.wasm engine described below. Install FFmpeg once on Windows: `winget install --id Gyan.FFmpeg --exact`, completely restart VS Code/HQ, check `ffmpeg -version`. Run `flutter test --dart-define=KONTRIOS_FFMPEG_TEST=true test/vocabulary_fast_upload_test.dart` for real conversion smoke test.

## Chrome audio conversion

Install Node.js LTS if npm is not already available. From the HQ repository run `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\setup-web-audio.ps1`. This installs exact versions of `@ffmpeg/ffmpeg` 0.12.15 and the single-thread `@ffmpeg/core` 0.12.10 into the ignored `web/vendor/ffmpeg/` directory. No desktop FFmpeg is required in Chrome. The first installation needs internet access and downloads the WASM engine (tens of MB); subsequent conversions run locally in a browser worker, without sending recordings to a conversion service. Re-run the setup on new checkouts and before web builds. Serve all generated engine assets under the same origin and include license notices and applicable corresponding-source obligations before distributing the web build. No cross-origin isolation required. 

Test: stop the existing app, `flutter pub get`, `flutter analyze`, `flutter test test/vocabulary_fast_upload_test.dart`, `flutter run -d chrome`. Drop a real AAC file, wait for conversion, play audio, check the MP3 slug, publish only a verified entry. Test missing engine, corrupt source, oversize input, alternate codec and retry. The real Dart FFmpeg smoke test uses the desktop engine; browser end-to-end conversion must be tested in the running web app. Mobile and bulk importer behavior unchanged.

## Conflict resolution

Fast Upload reports conflicts separately for image and audio with vocabulary reference counts. Reuse stored file discards the draft copy and previews/links the existing object. Use new version is offered only for zero-reference conflicts; a fresh check before publish fails if the original has gained a reference. New media uploads at an immutable `_v` plus 16 hexadecimal character suffix, without changing file_slug or deleting/overwriting any old object. Canonical and revision audio paths must match the language and slug; explicit revision paths also work in batch manifests. An implicit batch import preserves the approved existing revision. Storage garbage collection is separate; no auto-delete. The validation RPC returns reference_counts; both RPCs must be updated before this HQ version runs.
