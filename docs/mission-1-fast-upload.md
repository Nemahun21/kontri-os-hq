# Fast Upload rollout

Language vocabulary only. Open the existing Bulk Asset Import Studio and select Fast Upload. Windows drag/drop or browse; narrow screens stack. Local draft, 500ms read-only validation, canonical filenames, preview, explicit publish. Term reuse with another meaning is allowed after review; exact duplicate or slug/file conflict blocks create. Existing bulk imports retain missing-link recovery. Shared concept images remain available through bulk import. Original filenames are reported when present in the relevant folder; only canonical target collisions block upload. File bytes are retained for the current draft only. A failed database commit may leave uploaded but unlinked assets; retry after revalidation reuses byte-identical assets, never auto-deletes. For an uncertain response check the vocabulary list first.

Backend: apply reviewed mission-1-commit-vocabulary-import.sql and mission-1-check-vocabulary-draft.sql in the same project. Both require active admin and invoker RLS. No table or bucket changes. Fast Upload's final commit passes create_only; legacy callers do not. No Supabase service key in Flutter.

Local verification: flutter pub get (regenerates lockfile and plugin registration), flutter analyze, flutter test test/vocabulary_import_test.dart test/vocabulary_fast_upload_test.dart, flutter run -d windows. Test invalid file, same term/different meaning, duplicate, filename conflict, failed network, changing theme during validation, successful publish and next, existing bulk import.
